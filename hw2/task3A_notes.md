## Что сделано в задаче

Взяты сеть, MSE и ручной backpropagation из задачи 2. Затем аналитические градиенты проверены численно методом центральных конечных разностей. Если два способа дают почти одинаковые результаты, формулы обратного распространения, скорее всего, реализованы верно.

## Фокус обучения

- отличие аналитического и численного градиента;
- gradient checking;
- центральная конечная разность;
- замыкание через `lambda`;
- допустимая погрешность вычислений с плавающей точкой;
- применение `assert` для автоматической проверки.

## Главная формула

Производная функции `f` по параметру `p[j]` приближается так:

```text
df/dp[j] ≈ (f(p[j] + eps) - f(p[j] - eps)) / (2 * eps)
```

Численный метод медленный: для каждого параметра нужно два раза считать loss. Поэтому он подходит для проверки реализации, но не для обычного обучения большой сети.

### Численный градиент — строки 30–38

```python
def num_grad(fn, params, eps =1e-5):
```

Объявляет универсальную функцию численного градиента. `fn` должна принимать параметры и возвращать одно число; `eps` — очень маленький сдвиг.

```python
    gradient = np.zeros_like(params, dtype = float)
```

Создаёт нулевой массив той же формы, что `params`. `dtype=float` нужен, чтобы хранить дробные производные.

```python
    for j in range(len(params)):
```

По очереди проверяет каждый из четырёх параметров.

```python
        plus = params.copy()
```

Создаёт независимую копию параметров для положительного сдвига.

```python
        minus = params.copy()
```

Создаёт вторую копию для отрицательного сдвига. Копии не дают испортить исходные параметры.

```python
        plus[j] += eps
```

Немного увеличивает только параметр с индексом `j`.

```python
        minus[j] -= eps
```

Немного уменьшает тот же параметр во второй копии.

```python
        gradient[j] = (fn(plus) - fn(minus))/(2*eps)
```

Вычисляет центральную конечную разность и записывает приближённую производную.

```python
    return gradient
```

Возвращает численные производные всех параметров.

### Сравнение — строки 39–46


## Важное ограничение

ReLU не имеет обычной производной точно в точке `z1 = 0`. Если при проверке один из элементов `z1` окажется около нуля, численный и выбранный аналитический градиенты могут разойтись, даже если остальной код правильный.
