## Что сделано

Для функции `sin(x)` производная в точке `x = 1` найдена тремя способами: по точной формуле, прямой конечной разностью и центральной конечной разностью. Затем проверяется, как размер шага `h` влияет на погрешность, и строится график в логарифмическом масштабе.

## Фокус обучения

- производная как предел отношения приращений;
- прямая и центральная конечные разности;
- ошибка аппроксимации и ошибка округления;
- логарифмическая шкала;
- поиск лучшего `h`.

## Формулы

```text
Точная производная:       d sin(x)/dx = cos(x)
Прямая разность:          (f(x+h) - f(x)) / h
Центральная разность:     (f(x+h) - f(x-h)) / (2h)
```

Центральная формула обычно точнее при одинаковом `h`. Но бесконечно уменьшать `h` нельзя: при слишком малом шаге компьютер вычитает почти равные числа, и ошибка округления начинает расти.

## Код построчно

```python
import numpy as np
```

Подключает NumPy для `sin`, `cos`, массивов и логарифмической последовательности шагов.

```python
import matplotlib.pyplot as plt
```

Подключает Matplotlib для графика ошибок.

```python
def f(x):
        return np.sin(x)
```

Определяет исследуемую функцию `f(x) = sin(x)` и возвращает её значение.

```python
def df_true(x):
        return np.cos(x)
```

Определяет известную точную производную `f'(x) = cos(x)`. Она нужна как эталон.

```python
def derive_ford(f,x,h):
        return ((f(x+h)-f(x))/h)
```

Объявляет прямую конечную разность. Функция `f` передаётся аргументом, поэтому метод можно применять не только к синусу. Название `derive_ford` означает forward derivative.

```python
def derive_cent(f,x,h):
        return ((f(x+h)-f(x-h))/(2*h))
```

Объявляет центральную разность: значения берутся симметрично слева и справа от `x`.

```python
x0=1.0
```

Выбирает точку, в которой вычисляется производная.

```python
print("true:", df_true(x0) )
```

Печатает эталонное значение `cos(1)`, примерно `0.5403023`.

```python
print("forward h = 1e-5: ", derive_ford(f,x0, 1e-5))
```

Печатает приближение прямой разностью при `h = 0.00001`.

```python
print("central h = 1e-5: ", derive_cent(f, x0, 1e-5) )
```

Печатает центральное приближение с тем же шагом для сравнения.

```python
hs = np.logspace(-1, -12, 45)
```

Создаёт 45 шагов от `10⁻¹` до `10⁻¹²`, равномерно расположенных в логарифмическом масштабе.

```python
err_ford = np.array([abs(derive_ford(f,x0,h)- df_true(x0))
    for h in hs
])
```

Для каждого `h` считает абсолютную ошибку прямой разности и собирает результаты в NumPy-массив.

```python
err_cent = np.array([abs(derive_cent(f,x0,h)-df_true(x0))
    for h in hs
])
```

Так же вычисляет ошибки центральной разности.

```python
plt.figure(figsize =(6,4))
```

Создаёт график размером 6 на 4 дюйма.

```python
plt.loglog(hs, err_ford, "o-", label = "forward")
```

Рисует ошибку прямой разности. Обе оси логарифмические; `o-` означает точки, соединённые линией.

```python
plt.loglog(hs, err_cent, "s-", label = "central")
```

Добавляет ошибку центральной разности с квадратными маркерами.

```python
plt.gca().invert_xaxis()
```

Разворачивает ось X, чтобы большие `h` были слева, а маленькие — справа.

```python
plt.xlabel("h")
plt.ylabel("absolute error")
```

Подписывает оси: размер шага и абсолютная ошибка.

```python
plt.legend()
```

Показывает легенду для двух методов.

```python
plt.title("Finite-Difference Error vs Step Size")
```

Задаёт заголовок графика.

```python
plt.tight_layout()
```

Автоматически настраивает отступы.

```python
plt.show()
```

Открывает окно с графиком.

```python
print("best, h, forward: ", hs[np.argmin(err_ford)])
```

`np.argmin` находит индекс минимальной ошибки прямого метода, после чего по этому индексу выбирается лучший `h`.

```python
print("best, h, center: ", hs[np.argmin(err_cent)])
```

Аналогично выводит лучший шаг центрального метода.

```python
assert abs(derive_cent(f,x0, 1e-5)- df_true(x0)) < 1e-7
```

Проверяет, что ошибка центральной разности при `h = 10⁻⁵` меньше `10⁻⁷`.

```python
print("Task 1 OK")
```

Сообщает, что проверка пройдена.

## Ожидаемый результат

Центральная разность при `h = 10⁻⁵` почти совпадает с `cos(1)`. На графике ошибка сначала падает при уменьшении `h`, достигает минимума, а затем растёт из-за машинного округления.
